### webcrack 还原结果

- `inline-decoder-wrappers`：11530 处（1345 个解码器别名调用全部展开）

## 三、伤害计算体系（核心成果）

### 3.1 五路伤害模型

一次行动对 boss 的总伤害拆为五个独立计数器，分别结算与截断：

| 计数器 | 来源 | console 前缀 |
|---|---|---|
| `lastDmg` | 普攻/大招主体（atkMag/ultMag 倍率） | 평타/궁극 |
| `lastAddDmg` | "추가(追加)"型：평추가*/궁추가*（攻击力基准）、평추가+/궁추가+（固定值） | 추가 |
| `lastAtvDmg` | "발동(发动)"型：평발동*/궁발동*/방발동*/공발동*/행발동* | 발동 |
| `lastDotDmg` | 도트뎀（灼烧类，nextTurn 时统一结算） | 도트 |
| `lastRefDmg` | 반격*（受击反击） | 반격 |

### 3.2 主体伤害公式（getAtkDmg / getUltDmg）

四乘区相乘，任一乘区为负则整体归零（保底机制）：

```
dmg = getCurAtk() × (atkMag 或 ultMag)/100 × 乘区1 × 乘区2 × 乘区3 × 乘区4 × getInt()

getCurAtk() = floor(atk × (1 + 공퍼증[0]) + 공고증[1])     // 攻击%区 + 攻击固定区
乘区1 = 1 + 받뎀증[2]                                      // boss 受伤增加（全局乘区）
乘区2(普攻) = 1 + 일뎀증[3] + 받일뎀[4] + 받직뎀[13] + 받캐뎀[14] (+방뎀증[22] 仅 boss.def 时)
乘区2(大招) = 1 + 궁뎀증[5] + 받궁뎀[6] + 받직뎀[13] + 받캐뎀[14] (+방뎀증[22])
乘区2(发동) = 1 + 발효증[12] + 궁뎀증[5] + 받궁뎀[6] + 발뎀증[7] + 받발뎀[8] + 받직뎀[13] + 받캐뎀[14] (+방뎀증[22])
乘区3 = 1 + 가뎀증[9]                                      // 伤害增加（独立乘区）
乘区4 = 1 + 속뎀증[10] + 받속뎀[11]                        // 属性伤害 + 受属性伤害
```

其中 `atkMag/ultMag` 由 `setMnc(me, [hp1,mag1,...], asc)` 按技能等级注入；另有独立通道 `hpAtkDmg/hpUltDmg`（按 HP 基准的附加主体伤害，走同样乘区但不乘攻击力）。

### 3.3 附加伤害公式（actionMap）

追加/发动型 buff 触发时按 `*`（攻击力基准）/`+`（固定基准）两种 size 语义计算，且**同样过乘区与元素克制**：

```
평추가* → applyAddDmg(size/100 × getCurAtk() × atkAddCoef() × getInt())
평추가+ → applyAddDmg(size/100 × atkAddCoef() × getInt())
평발동* → applyAtvDmg(size/100 × getCurAtk() × atkAtvCoef() × getInt())
궁추가*/궁추가+ → applyAddDmg(…× ultAddCoef() ×…)
궁발동*/궁발동+ → applyAtvDmg(…× ultAtvCoef() ×…)
방발동*/방발동+ → applyAtvDmg(…× ultAtvCoef() ×…)      // 防御发动复用 ult 系数
피격발동반격*/반격+ → applyRefDmg(…× ultAtvCoef() ×…, me)
```

`atkAddCoef/ultAddCoef` = 乘区1×乘区2×乘区3×乘区4（不含发動系）；`atkAtvCoef/ultAtvCoef` 的乘区2 换为发動系组合（见 3.2）。

### 3.4 防御与溢出

- boss 防御(`boss.def=true`)时：所有五路伤害先乘 `(1 - max(0, 0.5 - 방경감[21]))`，即基础减伤 50%、`방경감`(防御减免穿透)可对冲；主体伤害还额外进乘区2 的 `방뎀증[22]`
- 溢出截断：单段伤害超过 `overflowDmg`(2^31-1) 时截断并置 `isOverflowed[k]=true`（五路各一位）；普攻按段数 `_0x359980`(n段) 先除以 n 判断再乘回——多段攻击单段不溢出即可全额
- `overflowed/atkOverflowed` 为历史遗留标志位

### 3.5 元素克制 getInt()

- 元素序：0화(火) 1수(水) 2풍(风) 3광(光) 4암(暗)；火克风(+50%)/风克水(+50%)/水克火(+50%)，被克 -25%；光暗互克 +50%
- `속상감[19]`(属性减伤) 线性削弱克制倍率：`1 + 克制系数 × (1 - min(속상감,1))`
- 任一方 element 为 -1/undefined（如自选属性 boss）→ 返回 1（无克制）

## 四、Buff 系统

### 4.1 四种 buff 形态（buff() 按参数个数分发）

| 参数数 | 形态 | 字段 | 谓词 |
|---|---|---|---|
| 6 | 回合型基本 buff | div=기본, type, size, name, turn=ex+GLOBAL_TURN, on | isTurn |
| 7 | 叠加型基本 buff | …, nest, maxNest | isNest |
| 10 | 回合型触发 buff | div=추가/발동, act(触发动作), who(目标), turn, ex(存续) | isActTurn |
| 11 | 叠加型触发 buff | …, nest, maxNest, ex | isActNest |

特殊 type：`아머`(护甲，挂时额外吃 `받아증[17]` 加成)、`도트뎀`(dot，挂时吃施加者的 `가지증[20]`，nextTurn 结算：`floor(size/100)×(1+받뎀증+받지뎀)`)、`방어`(置 def=true 不入列表)、`제거/on/off`(由 addBuff 触发引擎直接执行)、`힐/<빛·바람·불의 축복>`(触发治疗/祝福，排序置后)。

size 字符串协议：`'a'+id(5位)+百分比` = 按某角色当前攻击力%，`'b'+id+百分比` = 按某角色当前护甲（`getSize()` 解析；myCurAtk='a'/myCurShd='b'）。

### 4.2 触发引擎 addBuff(me, acts, div)

- `acts` 例：`["평","행동","공격"]`（普攻时）、`["궁","행동","공격"]`（大招）、`["방","행동"]`（防御）、`["피격"]`（受击）、`["힐"]`（治疗）
- 匹配 me 身上 `div==추가/발동 && act∈acts` 的触发 buff + `div==기본 && type∈actSet` 的本体型（평추가*/궁발동* 等 12 种）
- 执行顺序：힐/축복 排最后；제거→on/off→아머(收集后统一挂)→기본(查 actionMap 执行伤害)→발동(向 who 挂新 buff；who==all 全员；**who.id==0 且 me 是 boss 且受击 → 挂给 whoActed 行动者**，这是反伤/受击反馈进攻击者的通道)
- `armorUp(me, act, div)`：아머 类 size 落地前按 (1+궁/일뎀증)(1+가아증) 放大

### 4.3 23 种乘区类型表 txts

```
0 공퍼증攻击%↑  1 공고증攻击固定↑  2 받뎀증受伤↑(全局乘区)  3 일뎀증普攻伤害↑  4 받일뎀受普攻伤害↑
5 궁뎀증大招伤害↑  6 받궁뎀受大招伤害↑  7 발뎀증发动伤害↑  8 받발뎀受发动伤害↑  9 가뎀증伤害↑(独立乘区)
10 속뎀증属性伤害↑  11 받속뎀受属性伤害↑  12 발효증发动效果↑  13 받직뎀受直接伤害↑  14 받캐뎀受角色伤害↑
15 아머护甲  16 가아증护甲量↑  17 받아증护甲获得量↑  18 받지뎀受持续伤害↑  19 속상감属性减伤
20 가지증持续伤害施加量↑  21 방경감防御减免(穿透)  22 방뎀증防御中伤害↑
```

`getBuffSizeList(me)`：过滤 div==기본 && on && 未过期 && type∉buff_ex，按 txtsMap 聚合为 23 元向量（叠加型按 size×nest），再叠加 boss 的 `li` 向量——**boss 身上的"받X"类 buff 实质是全队共享的受伤乘区**。

### 4.4 语法糖族（角色定义 DSL）

```
tbf(me, type, size, name, turn|nest)     // 기본 回合型（5参，on=true 默认）
ptbf(me, act, who, type, size, name, ex, turn)  // 추가 触发回合型（8参）
atbf(...同上)                             // 발동 触发回合型（8参）
nbf(me, type, size, name, nest, maxNest) // 기본 叠加型（6参）
pnbf/atbf 同构                            // 추가/발동 叠加型（9参）
anbf(me, act, who, type, size, name, nest, maxNest, ex)  // 발동 叠加型（9参）
tbf(all, ...) → 递归展开到全体成员
```

（2024 明文版参数名：`buff(me,type,size,name,turn,on)` / `tbf(...)` 完全同构，证实该 DSL 两年未变。）

## 五、角色定义体系 setDefault(me, asc)

- 每个角色 = `case <id>:` 分支（10001 마왕 바알 起，共 237 人），注入 9 个生命周期钩子：
  - `ultbefore/ultafter`：大招前后（buff 铺垫/清理）
  - `ultimate()`：通常 = 条件检查 + `ultLogic(me)` (+cdChange)
  - `atkbefore/atkafter/attack()`：普攻同构
  - `leader()`：队长技（`hpUpAll(x)` 全队 HP%↑ + 常驻 buff）
  - `passive()`：被动（常驻 buff / 触发 buff 注册）
  - `defense/turnstart/turnover`：防御、回合始、回合末
- `ultbefore` 内 `switch(asc)` 按解放等级 1-5 取不同数值，`default:` = 5 级
- `setMnc(me, [hp1,mag1,...,hp5,mag5(,cd)], asc)`：按等级注入 atkMag/ultMag/cd
- `alltimeFunc[]`：常驻型角色（如每回合检查发動）注册回调，alwaysCheck() 驱动
- 钩子里的韩文字符串（"마왕의 육체1" 等）即 buff 实例名，供 setBuffOn/setBuffSize 定点操作、也用于 buff 摘要展示

## 六、黑名单角色的技术根源（实证）

反推直接证实了"黑名单 ≠ 无法生存，而是**模拟器算不准**"：

### 10153 할로윈 사탄（小撒旦/誕姬）

`setDefault` 第一行即 `buff_ex.push("<고급 할로윈 디저트 세트>")` —— **运行时向全局数组 buff_ex 追加条目**。`buff_ex` 是 getBuffSizeList 的排除名单，一旦 push，全局所有角色的 buff 聚合永久跳过该类型；同一队伍若另一角色依赖同名 buff 类型（或该 push 在多队模拟、快照回退 loadBefore 后不回滚），状态即被污染。`stack` 字段 + "디저트 폭식"叠层与 "성배의 메아리"回响（ultimate 中 setBuffSize/setBuffNest/setBuffOn 多点联动重置）构成跨行动的状态机，与反击触发（피격发動）组合时结算顺序无法静态保证。

### 10164 풍魁（风魁/花魁）

- `myCurAtk + id + 20` 动态攻击力绑定（수줍은 정취2 全队攻击固定值 = "自身当前攻击的 X%"），getSize 字符串协议
- `반격*` 265→397%（受击反击）+ atbf 피격 제거（受击后移除自身反击 buff）
- leader 技 `getElKind()==2`（恰好 2 种元素时全队 가뎀증50 + 발효증100 + anbf 피격→boss 받뎀증 0.8×叠50层）—— **피격 链式触发**：boss hit() → wind魁反击 → 攻击者 피격 → …，与杀气积蓄类（每回合 stack++）互相喂触发时循环深度不可控

即：黑名单 6 人（10002 Satan、10027、10056、10130、10164、10153）的共性是"反击/受击链 + 全局状态修改 + 动态绑定"三者交叉，javascript 事件式相互递归使确定性结算顺序难以维护，作者选择直接禁入组合而非算错。此结论同时解释了为何 24/10/16 加入模拟器、24/11-07 修公式、25-02-23 才禁组合（先试图修公式、修不动再禁）。
