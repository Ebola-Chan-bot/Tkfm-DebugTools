优化器提供两个互补的链接搜索入口，统一处理角色名单、中文别称、每角色羁绊、Boss 属性与 Boss 减益。

## 跨队搜索：从持有名单独立找最优 5 人队

正式入口是仓库根目录的 `搜索最优队伍.js --链接="完整 make 链接"`。它读取链接中的 `list`、`bond`、`bossEl` 和 `options`，然后完全由算法生成候选名单、站位和排程，**不读取 `data.json`，不参考 DB 起点，不迁移 DB 排程，也不按 DB 排名筛选**。链接模式自动强制 `--禁用种子`。

```powershell
node .\搜索最优队伍.js --链接="https://inittt.github.io/tenkaassist/make/?list=...&bossEl=dark&options=0,0,0,100,100,0,0,0" --出目录="D:\搜索产物\暗Boss" --终搜=3 --束时限=120
```

搜索阶段：全部合法 5 人名单的并行粗筛 → 入围名单 120 站位精扫 → 高分名单前瞻贪心与爬山精排 → Top 名单全站位深评 → 最终候选完整排程管线。108 人名单有 111,469,176 个组合，属于长跑任务；产物、进度和逐块检查点默认放在 `%TEMP%`，同一 `--出目录` 和相同参数重跑即可断点续搜。

`--只解析` 用于查看名单规模、实际战场条件和自适应预算；`--必须任一=id1,id2` 可要求每队至少包含其中一个角色；`--从头` 清空当前出目录的检查点。Boss/options、羁绊和禁用种子状态都参与检查点指纹，避免不同条件的结果混用。

链接没有 `bond` 时按模拟器缺省全员 5 绊；`options` 前三项是组队筛选条件，后五项是 Boss 减益。入口只计算非 ELV 的 13 回合 `dmg13`，含 `elv` 或非零 `hpUp`、`fit13t` 的链接会明确报错，不静默按错误目标搜索。

最终结果用独立新引擎显式传入 Boss 和 options 复算，与搜索值不一致时拒绝导出。粗筛/精扫的入围数量可用 `--入围=`、`--B名单=`、`--TopN=`、`--D名单=` 控制；缩小这些值只会减少已评估范围，不能把结果冒称为全空间最优。

`优化器/主程序.js --链接` 是限定起点的邻域搜索入口，链接模式同样默认禁用种子。它适合在链接中带 `起点=5个id` 后向外换人，不用于无起点的全池独立搜索。

## 单队精修：固定 5 人，搜索站位与动作排程

`搜索队伍.js` 保留中文别称输入方式，也支持 `--链接`。make 链接必须含 5 人的 `起点=`，simulator 链接则直接使用其 5 人 `list`：

```powershell
node .\优化器\搜索队伍.js --链接="https://.../make/?list=...&起点=10214,10196,10168,10147,10216&bossEl=dark&options=0,0,0,100,100,0,0,0" --细搜比例=0.9 --束时限=60 --输出=单队日志.txt --导出=单队结果.json
```

该入口枚举 120 种站位，每个合法站位都运行先验贪心与先验前瞻贪心，同站位取两者较高伤害作为粗评分；启用 DB 种子时，同集合种子也参与取优。默认将粗评分不低于榜首 90% 的全部站位纳入完整排程管线，并保留原输入站位保底，不再按固定 TopK 截断。`--细搜比例=` 取值范围为 `(0,1]`，例如 `0.95` 表示榜首向下 95% 的范围，`1` 表示仅并列榜首。

羁绊按角色 id 随站位重排，不会错误绑定到槽位。可用 `--原排列` 固定输入站位、`--只粗评` 只查看站位排名与细搜门槛、`--束时限=0` 跳过束搜索。

## 共享实现

`优化器/链接条件.js` 是链接解析、中文别称与战场条件注入的共享模块。`主程序.js` 和 `搜索队伍.js` 均通过它创建引擎，避免不同搜索阶段或不同 CLI 各自维护一套 Boss/options 逻辑。现有不带链接的调用仍按原无属性、无 Boss 减益、全 5 绊口径执行。
