```powershell

npm run build
npm run preview
```

本地地址为 <http://localhost:5510>。构建产物在本目录的 `dist/`，可部署到任意 HTTPS 静态目录；所有应用资源、manifest、Service Worker 均使用相对路径，可部署于 GitHub Pages 项目子目录。首次打开并显示“离线就绪”后，已缓存页面可断网运行。支持安装提示的浏览器会提供安装按钮，其他浏览器可使用自身的安装菜单。

战斗设置提供可选的“手动选择随机分支”，可在战斗过程中随时切换并保留当前进度，无需应用设置或重新开始：启用后遇到多个随机目标时逐项弹出候选供玩家选择，不再抽取随机数；选择序列写入对应操作，撤销、重做、导入导出与记录重放均按已保存选择复现。未启用时维持原随机结算与撤销后重随机规则。所有编队和操作记录只保存在浏览器本地，可导入导出 JSON。切换关卡保留当前已应用编队、站位及全部养成设置，未应用的编队草稿也继续保留，不会被目标关卡的默认队伍或旧阵容覆盖。各关分别保存敌方与模型参数、战斗操作和进度；目标记录与当前编队相同则恢复原进度，不同则先逐份备份原记录，再以当前编队重新开始目标战斗，刷新后可在编队页导出最近备份。刷新恢复最近使用的关卡；未应用草稿仅在当前页面保留。CSV 包含逐回合伤害、有效及理论治疗、溢出治疗、护盾生成、护盾吸收、承伤和存活数。重置战斗只回到当前配置的初始状态，不删除行动记录；游标归零后仍可用重做逐项重放，重新执行动作沿用现有重随机与同结果保留规则。应用编队会先比较当前战场：角色与养成完全相同则保留当前战斗及全部记录；角色和站位相同但养成（羁绊、星级、调教、等级、突破、潜力、解放或ELv选择）不同则按原操作回放，遇到首个非法动作即停在之前；角色名单或站位变化才重置当前战斗并自动归档原记录。模型设置会重置当前战斗。撤销与重做通过确定性操作重放实现。

页面切换由用户点击页签或“完整记录”等明确导航入口触发。切换关卡、应用编队、应用战斗设置、载入文件和重置战斗都只刷新当前页，不自动进入战场。当前浏览器标签页会记住用户选择的视图，刷新后恢复；这不表示未应用的编队草稿会自动保存，草稿仍可通过应用或导出保存。

# 编队与面板

编队支持1至5位角色。可用“添加角色”和每行的移除按钮调整人数，至少保留1位、最多5位；移除后站位顺次前移，第一位为队长。战场、回合报表、自动行动、存档与回放使用实际人数，不补入隐藏角色；夏日尾声仍保留原本五名敌人。技能中明确要求五人或指定站位的条件仍按原技能判断，不因少人队伍自动满足。

编队每行的角色选框是可输入搜索的组合框：点击聚焦后清空文字（当前角色转为占位符）并列出角色池全部候选，输入即按编号、全名、简称及全部登记别名过滤，支持子串与逐字子序列匹配——例如输入“拉尤”命中别名登记的啦啦队长 尤妮思，输入“队长尤”也能命中。键盘上下键移动高亮、回车选定、Esc 或失焦还原当前角色；候选项显示编号与常用中文别名，已在其它站位的角色置灰不可选，点击候选直接换人。选定只修改编队草稿，仍需“应用编队”才替换当前战斗。

角色池支持粘贴TenkaAssist推荐团队复制代码，标签链接到[tenkaassist的have模块](https://inittt.github.io/tenkaassist/have/)并在新标签页打开；格式为队员段与羁绊段以冒号连接，采用其64进制编码。合并不会删除已有角色；同编号只以导入值更新羁绊，已有星级、调教、等级、突破、潜力、解放及ELv选择保持不变。新增角色或双方均缺失的养成字段使用最大值：5星、调教3、60级、ELV突破20、潜力12与全节点、可用最高解放，所有ELv技能均为未强化。未知角色、非法编码、重复角色或羁绊不匹配会整体拒绝，不保存部分结果。搜索与职业、属性筛选在桌面和手机均保持单行。

编队页的“导出编队”保存当前草稿为独立文件，包含角色顺序、羁绊、星级、调教、普通等级、潜力阶数与六节点、解放及ELV等级和单选技能，不包含关卡、战斗进度、手填生命／攻击或技能脚本。“载入编队”从该文件恢复草稿，确认后点击“应用编队”才替换当前战斗；与顶部导入／导出完整战斗记录的功能独立。空队、超出五人、重复角色、无效角色及不合法养成会被拒绝，载入失败不改动当前编队。

“战斗记录”页提供历史归档：导入新记录、或点“应用编队”改养成重开前，当前战斗都会先自动存入归档（有操作才归档，校验失败或无操作则不归档），也可随时“保存当前战斗”手动归档，最多保留8条；存储空间不足时从最旧归档开始丢弃重试并提示。每条归档显示结果、回合、首领生命、存活、操作数与队伍潜力（形如“潜力 5/7/5/5/5 · 最高 7×1人”），支持查看、恢复、导出和删除。“查看”在桌面端打开右侧对照面板、手机端打开底部抽屉，面板独立滚动、跨战场/编队/角色池/记录各页签持续保持，不影响主战斗；因此典型流程——先改角色池养成再“应用编队”手动重打一场——原战斗会自动归档，全程可开着对照面板一边看旧记录一边打新战斗。面板摘要下方同时列出该归档每人的养成快照，便于与本场逐位对照。恢复归档等价于重新导入，当前战斗先自动归档、被恢复的归档条目移除，不会丢失任何一方。归档与记录一样存于本地并跨刷新保留，回放失败会明确提示且不改动当前战斗。

战场页与战斗记录页都有“本场养成”速览区，逐位显示本场战斗每名队员的潜力（徽章式单列）、潜力节点数、等级、ELV突破、星级、羁绊、调教、解放与ELv技能项数，标题右侧给出“最高潜力 7 × 1人 · 潜力合计 27”这类汇总，低潜力优化时可直接看出上限由谁抬高，金色徽章只标在该成员上、全员同潜力时不高亮。点击任意一行打开该角色的详情弹窗，其中“本场养成快照”另附完整字段与已选ELv技能名称及说明。速览读的是战斗配置与战斗状态里的队伍快照，因此之后修改角色池养成或改换编队都不会改变已打记录显示的潜力。

角色输入框用于搜索游戏中真实存在的SSR角色，不是角色创建器。支持范围仅限SSR，不支持SR、R、N；当前资料快照包含188位SSR及201个技能版本，188位均具备参考面板。可输入名称、编号、资料编号或“编号 完整名称”；匹配后载入真实编号、名称、职业、属性和已有面板，不生成任何自定义编号，也不允许改成虚构职业或属性。

完整名称优先唯一匹配，简繁全名可直接使用；简称或部分名称存在多个候选时必须进一步选择，不擅自取第一位。比如“魔剑”可能指不同角色，而“终焉魔剑薇塔”可唯一匹配编号10212。未知名称、未知编号、编号与名称不符以及同队重复编号均被拒绝。

真实角色身份与技能建模是两件事。188位SSR现在统一使用真实文本模型，不再以原8位手工模型兜底。当前普通技能、队长、星级被动、潜力被动及16位角色的真实三阶段解放均进入同一编译与执行流程；星3至5、羁绊1至5及可用解放阶段共3540档。命令行覆盖报告包含逐档结果、37条ELv定义、资料指纹及校核依据，不在编队页面显示或导出；未知目标、未知效果、空普攻／必杀和不适用ELv选择均明确阻断。编译完整、运行无异常和官方实测正确是三个不同结论，不能互相代替。

旧技能规则记录不能按当前规则直接回放。载入本地旧记录时逐份保存备份，不覆盖此前备份；编队页可以导出原始记录，草稿的解放阶段须重新确认。虚构角色或占位技能不继承为真实模型，未知或重名输入仍待逐位选择，不从虚构编号猜角色。新的默认队伍只使用真实SSR。

普通等级倍率为 `1.1^(等级-1)`，星级倍率为 `(1+0.2×星级)`，调教分别对应0%、5%、15%、30%。潜力按角色真实类型累计：低于所选阶的节点已全部开启，当前阶仅累计勾选节点，HP与ATK分别求和后各自相乘；被动节点只解锁对应潜力技能，不误算为属性百分比。解放基础面板与ELV累计加成另计，例如ELV1仅攻击增加0.6%，ELV2两项各增加0.6%，ELV20两项各增加6%。面板公式由 `TPlayerChar.GetHp(2参)`@0x80028eae28 包装的共享计算函数@0x80028eaea8（GetAtk同构）汇编定案：float前缀四乘槽按 fmul 序=基础×潜力基点因子(基点×0.0001f)×解放百分比因子(百分比×0.01f)×调教百分比因子(百分比×0.01f)×ELV基点因子(基点×0.0001f)，转double后×Math.Pow(1.1,等级-1)再×星级因子(1+0.2double×星)，向下取整——星级走double尾支、解放在float前缀内，与旧"星→调→潜→ELV float前缀+解放double尾"模型相反；潜力槽函数@0x80028ebd0c遍历节点表累加u16基点、解放槽@0x80028eb8ac按char+0x50三位标志查表累加u8百分比、ELV槽@0x80028ebf44出基点，asm中s8=s11/s9=s10为同两静态结构各复制两次故仅0.0001f/0.01f两常数。达芙妮10184（4星调2潜9节点TTTFFF、ELV0、解放0、60级）旧模型2385454、游戏实测2385455，新模型2385455.0796→2385455命中；八锚（达芙妮2385455/兔姬1651680/巴尔2879294/圣剑2222473/枪匠2870268/伊2057972+464127/毛毛3533589/尤妮思2343896）联立全过，满养成188角色仅天使长10007生命3561358→3561357、偶像10026攻击948241→948240（均无实测锚），SP4一回杀记录（含解放3角色）重放逐位不变。毛毛10198五星、调教3、潜力12全节点、ELV20实测基础生命3533589，队长50%增益为1766794，最终5300383；尤妮思10168四星调2潜7前4节点ELV20的2343896、枪匠2870268及全部夏日实测伤害链同时保持。兔姬10193三星调1潜4节点TFFTTT、ELV0实测生命1651680保持；[测试/兔姬生命-1651680.json](测试/兔姬生命-1651680.json) 的中间值描述属已退役旧模型，锚点整数仍有效。各倍率不在中间基准取整。进场后的最大生命增益另按原执行器hpUpMe处理：每项增益独立向下取整后加到初始生命，增益基准就是角色自身进场面板整数，与面板同源同值，不再为参考角色表另走一条60级参考HP基准。枪匠10216在四星、调教3、潜力9阶节点TTFFTT、ELV20、羁绊4配置下面板为2870268，队长万巴55%增益为`floor(2870268×0.55)=1578647`，最终`2870268+1578647=4448915`，与用户游戏内实测一致；旧参考表基准在该配置下给出2870266，会算成4448914差1，已废弃。旧记录中“增益基准2704673、最终4192246”的示例随该机制一并撤回，其与首回合592308同属早期抄录误差 lineage，不再作为锚点。

ELV突破要求60级及潜力5满或6以上，界面和战斗结算均校验资格。降低普通等级或潜力使资格失效时，ELV归零并取消未解锁的突破技能；切换潜力阶数时清空新阶节点选择，之前各阶按已完成计算。生命／攻击输出为进场前属性，队长、被动及所选ELv技能在战斗内独立结算，不重复叠加。

普通技能的修订号不是解放等级。默认使用截止日期为空的当前修订，历史说明保留；解放从独立资料按阶段1、2、3累积覆盖指定技能。露露阶段1替换指定技能，阶段2基础HP／ATK提升10%，阶段3进一步替换队长与被动，不能把普通历史修订2当作解放1。

ELv不是基础调教。折叠选择区收录37条真实技能，只显示当前SSR职业和属性适用的项目；保存真实编号、资料指纹并显式参与初始技能。每个强化分类单选、最多生效一项，不同分类和角色互不干扰；选择“未强化”可清空该类，默认不自动选择技能。同类多选的旧配置或导入记录会被拒绝，须重新选择，不擅自保留其中一项。职业强化Ⅰ、通用强化、属性强化、职业强化Ⅱ分别在ELV5、10、15、20解锁，未达到等级的选项禁用，降低等级取消超出门槛的已选技能；程序导入的未解锁选择也拒绝进入战斗。达到门槛不代表账号已经消费材料取得技能，仍须按游戏内实际情况显式选择，不自动生成账号养成方案。

文本模型支持命名子技能、相对阵营、职业／属性组合与最高最低筛选、层数和队伍条件、概率、生命／护盾／指定角色攻击基准、叠层保护、持续效果、吸血、祝福、控制、清除和冷却变化。随机状态保存在战斗JSON中，固定种子可确定性回放。事件按动作批次去重，多段伤害不冒充多次受击；同一具名状态和授予来源共享真实层数上限。

我方普攻／必杀先完成主体、追加和发动效果，再统一派发敌方受击事件；受击引发的后续事件仍在同一批次结算并去重。这个时点对应原包 atkLogic／ultLogic 在 act_attack／act_ultimate 后才调用 boss.hit，避免主体伤害触发的“被攻击时”增益提前改变同次行动的追加段。

# 自动敌方行动

新建战斗默认启用自动敌方。玩家选择我方行动后，敌方自动结算并推进下一回合；没有任何按职业、必杀冷却或关卡替我分配普攻、必杀、防御的策略。“敌方回合”只结算已经完成的当前敌方回合，“连续敌方”只连续处理敌方行动，遇到需要玩家选择的回合立即暂停，不自动出招、不自动防御、不自动选目标。受控角色的自动待机是状态结算，不属于自动策略。旧记录保留可导出，不会按新语义静默重算；确认编队和面板后重新应用当前模型。

“战斗记录”展示回合统计及玩家可理解的行动、伤害、治疗和效果，技能显示名称而不是内部编号。底层仍保留AI命中轨迹、条件与规则槽位供内部核查，但网页不展示独立的AI诊断表或导出入口。战斗记录导入导出仍包含配置与我方操作，可用于恢复和重放。

`解析敌方行动.mjs` 是只读原包分析工具，不进入发布产物。EnemyAI 整表1225条，每条703字节，含20个35字节规则；两关六名敌人的43条记录均逐字段对照。运行规则在 `敌方行动规则.mjs`，不加载原包或反混淆计算器。

```powershell

```

直接证据包括技能引用、周期与余数、血线参数、人数参数及选敌码。原包测试敌人60136／60137的技能23976—23991明确写出条件60—65分别检测双方当回合普攻、必杀、防御次数。
